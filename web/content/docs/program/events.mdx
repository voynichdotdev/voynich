## How an event is carried

Events are emitted with Anchor's event CPI: the program calls itself, and the event is the data of that inner instruction. They are not in the transaction's log messages, so a full or truncated log never hides one.

To read the events of a transaction:

1. Take the transaction's inner instructions whose program is the `voynich` program.
2. Keep those whose data starts with the 8 bytes `e445a52e51cb9a1d`. Their only account is the event authority, the PDA `["__event_authority"]`, as a signer.
3. The next 8 bytes are the event's discriminator from the table above.
4. The rest is the event's fields in order, Borsh-encoded.

Addresses are 32 bytes, integers are little-endian, a `string` or `bytes` or `Vec` starts with its length as a `u32`, and `ModelStatus`, `CallStatus` and `PriceUnit` are one byte with the values in [Accounts](/docs/program/accounts#model).

The API reads the same events and serves them as a stream: see [HTTP API: Overview](/docs/api/overview).
